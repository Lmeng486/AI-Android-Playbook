# R-0202: 根目录与伪文件系统 (/proc, /sys) 禁扫

## 规则
禁止对 `/`、`/proc`、`/sys`、`/data`、`/data/data` 执行原生无限制递归搜索。这些路径下的权限拒绝会直接中断整条命令，且错误码 `os error 13 (Permission denied)` 极易引发 Agent 产生"权限不足需要 sudo 或 chmod"的连续幻觉螺旋。

## 反例
```bash
find / -name "*.log"
# 炸点：/proc/self/task/*/ 下的权限拒绝中断整条 find
# 返回：Permission denied (os error 13)
# Agent 常见误判：以为需要 sudo 或 chmod

grep -r "config" /sys
# 炸点：/sys 是内核虚拟文件系统，大量动态节点读取返回 EIO (I/O error)
# 结果：命令挂死、耗尽 Token 或异常退出
```

## 正例
```bash
# 限定具体业务目录 + 深度 + 不跨挂载点 (-xdev)
find "$HOME" -maxdepth 4 -xdev -name "*.log"

# 使用 ripgrep（rg），默认尊重 .gitignore，性能优异且自动忽略隐藏系统伪文件
rg --files "$HOME" | grep '\.log$'

# 跨目录时显式枚举子目录，不扫全盘
find "$HOME" "$PREFIX" -maxdepth 3 -xdev -name "*.conf"
```

## 为什么
- `/proc` 是 procfs，进程目录权限随进程 owner 动态变化，非 root 权限下必然触发海量 `EACCES`。
- `/sys` 是 sysfs，大量内核驱动文件单次不可读或返回 `EIO`。
- `/data/data` 下其他 App 的私有沙箱对当前应用不可读。
- `find` 命令默认遇到未捕获的权限拒绝时会报错并中断遍历。即使追加 `2>/dev/null`，遍历高频创建/销毁的 `/proc` 仍可能导致命令卡死。

## 降级路径
如果确实需要定位根目录层级的文件：
1. 先 `ls -la /` 确认顶层目录清单，定位具体属于哪个子目录。
2. 加上 `-xdev` 阻止跨入伪文件系统。
3. 显式指定 `-maxdepth`（如 2 或 3）。
4. 仍失败则熔断，向用户报告："根目录与系统分区扫描不安全，请指定具体子目录。"

## 熔断条件
- 连续 2 次触发 `os error 13` / `Permission denied`。
- 或针对根路径的扫描执行超过 30 秒无有效输出。
- 或搜索路径命中 `/proc`、`/sys`。

## 适用范围警告
- Android 14+ 对 `/data/data` 的沙箱隔离策略进一步收紧。
- 部分厂商定制 ROM 将 `/proc` 挂载为 `hidepid=2`，行为与标准 Linux/Android 有显著差异。
