# R-0203: 搜索必须显式限制深度与文件系统边界 (-maxdepth, -xdev)

## 规则
在移动端 Linux (Termux / PRoot) 环境下执行 `find` 时，必须显式附加 `-maxdepth` 与 `-xdev`。未做限制的递归将进入系统挂载点、`/proc` 进程树或深层构建缓存，导致命令挂死或产生海量 Token 垃圾。

## 反例
```bash
find . -name "*.log"
# 风险：若当前目录处于 /、/data 或根附近，将一路深潜进入系统树
# 风险：无 xdev，跨入 /sdcard 外部存储，触发 FUSE 性能骤降或权限错误
```

## 正例
```bash
# 推荐参数组合：限制目录 + 深度 3-4 + 单一文件系统
find "$HOME" -maxdepth 4 -xdev -name "*.log"

find "$PREFIX" -maxdepth 3 -xdev -type f -name "*.so"

find /sdcard/Download -maxdepth 2 -type f -name "*.apk"
```

## 参数建议
| 参数 | 推荐值 | 核心依据 |
| :--- | :--- | :--- |
| `-maxdepth` | `3-4` | 绝大多数源码与配置在 3-4 层以内；更深层多为 `.git`、`node_modules`、构建产物 |
| `-xdev` | 必带 | 阻止跨越挂载点，防止误入 `/sdcard`、`/proc`、`/sys` 等虚拟或外部存储 |
| `-type f` | 推荐 | 仅过滤文件，过滤目录节点，减少匹配噪音 |

## 降级路径
如果带参数后仍未检索到或响应超时：
1. 使用 `rg --files`（自动遵循 `.gitignore` 并忽略冗余目录）。
2. 使用 `ls -la` 逐层确认真实目录命名后做精准查找。
3. 熔断并向用户反馈已检索的具体范围。

## 熔断条件
- 带 `-maxdepth 4 -xdev` 执行仍超过 30 秒。
- 连续 2 次无结果且目录存在。
