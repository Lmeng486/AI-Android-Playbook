# R-0201: 共享存储 /sdcard 是 noexec，不要 chmod +x

## 规则
Android 共享存储（`/sdcard`、`/storage/emulated/0`、`/mnt/sdcard`）默认挂载为 `noexec`，且叠加 sdcardfs/FUSE 安全限制。`chmod +x` 在该分区上静默失败（无报错返回），执行 `./script.sh` 会返回 `Permission denied`，且错误信息不会提示是 noexec 导致的。

## 反例
```bash
chmod +x /sdcard/script.sh
/sdcard/script.sh
# 结果：Permission denied
# 且 chmod 不报错，制造"权限已给"的假象
```

## 正例
```bash
# 复制到应用私有目录（ext4 可执行分区）
cp /sdcard/script.sh "$HOME/script.sh"
chmod +x "$HOME/script.sh"
"$HOME/script.sh"

# 或使用 Termux / PRoot 临时目录
cp /sdcard/script.sh "$PREFIX/tmp/script.sh"
chmod +x "$PREFIX/tmp/script.sh"
"$PREFIX/tmp/script.sh"
```

## 为什么
- `/sdcard` 挂载参数含 `noexec`，Linux 内核层面直接拒绝执行该分区上的二进制文件与脚本。
- `chmod +x` 修改的是文件权限位（VFS 抽象层），不改变挂载属性，因此"成功"但不生效。
- sdcardfs / FUSE 存储包装层进一步限制了可执行文件的 `mmap(PROT_EXEC)`。
- `$HOME` 位于应用私有目录（如 `/data/data/com.termux/files/home`），底层为 ext4/f2fs 文件系统，支持可执行属性。

## 降级路径
如果复制到 `$HOME` 失败（存储不足 / 路径不存在）：
1. 检查 `df -h "$HOME"` 确认剩余空间。
2. 改用 `$PREFIX/tmp` 或 `/tmp`。
3. 仍失败则熔断，向用户报告："无法在可执行分区找到落脚点，请确认存储空间与权限。"

## 熔断条件
- `cp` 到 `$HOME` 和 `$PREFIX/tmp` 均失败。
- 或 `$HOME` 所在分区剩余空间 < 目标文件大小。

## 适用范围警告
- Android 10+ 的 Scoped Storage 进一步限制 `/sdcard` 的访问路径。
- 部分厂商定制 ROM（如 MIUI / HyperOS / ColorOS）对 `/sdcard` 的挂载参数有额外严格审计。
